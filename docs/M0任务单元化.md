# M0 任务单元化（多程序员并行方案）

> 目标：把 M0（Agile 1 第一阶段）拆成**可并行**的工作单元（Work Unit），
> 每个单元 = 独立 issue + 独立文件面 + 独立验收，支持 4 人同时开工。
> 原则：**文件面零重叠**（并行不冲突）、**依赖显式化**（波次调度）、
> **每单元可独立合并**（各自分支 + PR）。

## 3. GitHub 组织（issue 即单元容器）

| Issue | 单元 | 挂载 | labels |
|---|---|---|---|
| #1 M0-1 kernel 骨架+事件契约 | U1+U2+U3（S3-S5） | Agile 1 | kind/skeleton scope/kernel priority/P0 |
| #2 M0-2 切片提取器+BM25 MVP | U4+U5+U6 | Agile 1 | kind/feature scope/kernel priority/P0 |
| #3 M0-3 Reasonix fork 适配 | U7+U8+U9 | Agile 1 | kind/feature scope/adapter priority/P0 |
| #4 M0-Gate 假设验证 | U10 | Agile 1 | kind/feature scope/kernel priority/P0 |

每个 issue 正文 = 蓝图摘要 + 单元 checklist（`- [ ] Ux ...` 带依赖标注 `[dep: Uy]`）。
**并行约定**：单元间文件面零重叠 → 各单元独立分支（`feat/u4-slice-core` 等）→
合入 `feat/kernel-skeleton`（U1-U3）或 `feat/slice-mvp`（U4-U6）、`feat/fork-adapter`（U7-U9）
→ 冲突只可能发生在合并点（由负责人协调）。

## 4. 多人协作规则（防冲突）

1. **文件面契约**：改动前先认领单元，改动范围不得超过该单元文件面；
2. **接口冻结**：U1 定型的接口（Store/Index/Embedder/Decider/Prefetcher/Engine）
   即"并行契约"，U4-U6 不得改签名（改需在 #1 讨论）；
3. **共享常量**：τ/τ' 等阈值常量放 `kernel/cache/params.go`（U1 建，U6+ 只读）；
4. **合并节奏**：每人每日至少推一次分支；负责人每完成一个波次合入主干分支一次；
5. **验收门**：每单元合入前 `go vet ./... && go test ./...` 绿（fork 单元另有
   Reasonix 侧测试）。

## 5. 并行时间线（4 人）

| 周 | 波次 | 里程碑 |
|---|---|---|
| 周 1 | 波 1（U1/U4/U5/U7） | 接口冻结 + 切片/BM25/旁路首版 |
| 周 2 | 波 2（U2/U6/U8） | CLI 可用 + 注入通道通 |
| 周 3 | 波 3（U3/U9） | tag v0.1.0 + 演示报告 |
| 周 4 | 波 4（U10） | **M0 Gate 决策** |

> 单人模式同样适用（按波次顺序做）；4 人模式总工期 ≈ 3-4 周（原 2-3 周单人
> 略有压缩，但关键是**并行面铺开**：波 1 的 U4/U5/U7 是风险最高的长任务）。

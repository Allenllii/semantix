# M0-Gate 假设验证决策报告（U10）

> 日期：2026-08-09 · 决策人：维护者 · 结论：**有条件继续（CONDITIONAL CONTINUE）**

---

## 1. M0 假设回顾

> "使用 coding agent 时，垂类任务产生大量**相似中间产物**；这些中间产物可以被切片化、跨会话复用（注入/缓存），从而**降低成本、提升完成速度**。越专业越聚焦 → 命中率越高。"

## 2. 证据汇总

| 假设成分 | 验证方式 | 结果 | 证据 |
|---|---|---|---|
| 中间产物可切片化 | U4 提取器（P/T/R 切片） | ✅ | turn 切分 + 工具序列 n-gram，12 测试 |
| 可检索复用 | U5 BM25（CJK 分词） | ✅ | scope 过滤 + 排序正确性测试 |
| **跨会话闭环** | U7 事件旁路 + U8 注入 | ✅ | `TestSessionBReusesSessionA`：会话 B 自动注入会话 A 切片 |
| **成本节省 ≥20%** | U9 成本对比 | ✅ **79.8%** | `docs/reports/m0-cost-comparison.md`（保守参数下仍 ≥30%） |
| 命中率 ≥70%（真实数据） | M0-2 `verify` 回放工具 | ⏳ **待用户真实数据** | 工具已交付（4998b98），合成数据命中 100% |
| 越聚焦命中越高 | verify 分组统计 | ⏳ 待真实数据 | 机制上成立（BM25 scope 过滤） |

## 3. 决策：有条件继续（CONDITIONAL CONTINUE）

**继续的理由**：
1. **技术可行性已验证**：切片提取 → 检索 → 跨会话注入的完整闭环跑通，全链路 20+ 测试全绿
2. **经济性假设强成立**：成本节省 79.8%（目标 20%），且在保守参数扰动下仍 ≥30%——不是"勉强达标"而是"远超达标"
3. **工程资产可复用**：kernel 八包 + CLI + 事件契约 + 安全基线（0600 存储/标记转义/原子写），无论 M1 方向如何都不浪费
4. **风险可控**：无外部依赖、零第三方依赖、本地优先

**继续的条件（M0-Gate 通过门槛）**：
1. **真实数据命中率 ≥70%**：用户用 `verify` 跑真实会话（`semantix verify --session <目录>`），30 天内完成
2. 若真实命中率 <70%：不判定止损，而是**先调 extractor 粒度**（turn 级 → 子任务级）再测一轮；两轮仍 <70% 才触发止损评审
3. M1 规划不得扩大投入（保持单 kernel 二进制 + 零依赖原则），直至真实数据达标

## 4. 若继续：M1 范围建议（首个可下载 agent，Agile 1）

```
P0（发布必须）：
- U11 真实数据达标（verify 回放 ≥70%）
- U12 embedding 语义检索（kernel/embed 落地：本地 miniLM 或远端 API）
- U13 L2 注入接入真实 harness（Reasonix fork 挂载点②③）
- U14 打包发布（单二进制 + 配置 + 文档）

P1（体验增强）：
- U15 切片评分/进化闭环（kernel/evolve 最小版：命中/拒绝信号 → 权重）
- U16 L3 结果复用（指纹 + mtime 失效）
- U17 成本仪表（Usage 事件 → 节省统计）

P2（暂缓）：
- U18 投机预取（kernel/prefetch）
- U19 灰色地带三级阈值（Issue #7）
- U20 LLM judge 验证（Issue #8）
```

## 5. 风险登记

| 风险 | 等级 | 缓解 |
|---|---|---|
| 真实数据命中率不达标 | 中 | 先调 extractor 再止损评审（见 §3） |
| 注入改变模型行为（副作用） | 低 | 标记转义已防攻击；行为影响在 U13 接入后实测 |
| 前缀缓存依赖厂商策略 | 低 | 注入块稳定是充分条件非必要条件（输出复用仍省钱） |
| 单点维护者风险 | 低 | 协作者已参与（U5/U6/site/GEO），M1 保持多人并行 |

## 6. 结论

**M0-Gate：通过（有条件）**。技术可行性 + 经济性双验证达成；真实数据命中率是唯一遗留门槛，其验证工具已交付。M1 按 §4 范围推进，先做 U11（真实数据）与 U12（语义检索）。
